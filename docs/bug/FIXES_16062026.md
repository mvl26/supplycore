## 1. Ràng buộc PO theo HĐ khung (L12, L13, L14, T12)

**File:** `supplycore/supplycore/doctype/sc_purchase_order/sc_purchase_order.py`

| Mã lỗi | Quy tắc thêm | Vị trí |
|--------|--------------|--------|
| `SC-E027 FC_SUPPLIER_MISMATCH` | NCC của PO phải trùng NCC đã ký HĐK | `_validate_against_framework_contract` |
| `SC-E028 ITEM_NOT_IN_FC` | Chỉ cho đặt vật tư nằm trong HĐK | nt |
| `SC-E029 FC_QTY_EXCEEDED` | SL/dòng (gộp theo item) ≤ `remaining_qty` của HĐK (L14) | nt |
| `SC-E030 PO_DELIVERY_BEFORE_ORDER` | Ngày giao ≥ ngày tạo PO (L13) | `_validate_delivery_date` (validate) |
| `SC-E-QTY` | SL > 0 mọi lần lưu (kể cả Draft) (T12) | `_validate_line_quantities` (validate) |
| `SC-E-RATE` | Đơn giá > 0 khi GỬI PO (before_submit) | `_validate_rates_before_submit` |

**Lưu ý thiết kế:** đơn giá > 0 chỉ chặn ở `before_submit`, KHÔNG chặn ở Draft — để
không phá luồng auto-tạo PO nháp (vd `sc_alert.py` tạo PO `rate=0` cho người dùng điền sau).
Tổng tiền vượt hạn mức HĐK (`SC-E002 FC_EXCEEDED`) vẫn giữ nguyên.

**Kiểm thử** (console, HĐK `SC-FC-2026-792584`):
```
PASS T12 qty=0 / qty=-5 → SC-E-QTY
PASS T12 rate=0 Draft → cho phép; rate=0 khi gửi → SC-E-RATE
PASS L13 ngày giao quá khứ → SC-E030
PASS L12 sai NCC → SC-E027 ; item ngoài HĐK → SC-E028
PASS L14 SL 2000 > còn 1000 → SC-E029
PASS PO hợp lệ → không chặn ; Alert auto-PO Draft (rate=0) → insert OK (không regression)
```

## 2. Quality Inspection (L17, L19, L20, T06, T15-QC)

**File:** `…/doctype/sc_quality_inspection/{sc_quality_inspection.py, .json}`

- **L17** `SC-E032 QC_RESULT_ACTION_CONFLICT` (`_validate_result_action`, gọi ở `before_submit`):
  chặn cặp mâu thuẫn — Đạt + Trả NCC / Yêu cầu thay thế; Không đạt + Chấp nhận / CN có điều kiện.
  Vẫn cho **Đạt + Chấp nhận có điều kiện** (luồng Conditional cũ).
- **L19/T15** `inspected_by` đặt `read_only` + `before_submit` ghi đè = `frappe.session.user`
  (người kết luận QC chính là người kiểm, không gán hộ).
- **L20/T06** QC không được sửa dữ liệu phiếu nhập — **enforce 2 lớp**:
  - *Backend (chính, authoritative)* `_sync_from_receipt()` gọi trong `validate()`: ép lại
    `item / batch / received_qty` theo đúng dòng phiếu nhập gốc (`pr_item_ref`). Dù người dùng
    POST thẳng sửa số, save sẽ **snap về nguồn**.
  - *UI* đánh `readonly` cho `purchase_receipt/item/batch/received_qty/inspected_by` trong
    **SPA schema** (`frontend/src/schemas.js`) + JSON doctype.
  - ⚠ Lưu ý kỹ thuật: `read_only` của Frappe là **client-side**, và SPA dùng `FORM_SCHEMAS`
    (schemas.js) chứ KHÔNG đọc meta doctype → vì vậy bắt buộc phải khoá ở `schemas.js` (UI) +
    `_sync_from_receipt` (backend) mới thật sự chặn. Chỉ sửa JSON là **vô hiệu** với SPA.

**Kiểm thử:**
```
PASS L17 4 cặp mâu thuẫn → SC-E032 ; 4 cặp hợp lệ → không chặn
PASS read_only meta áp đúng (purchase_receipt/item/batch/received_qty/inspected_by = 1)
PASS T06 5/5 QI mẫu: received_qty khớp PR.qty (không còn 0)
PASS L20 tamper: sửa received_qty=99999 + đổi item → sau validate snap về đúng phiếu nhập gốc
```

## 3. Tồn kho chỉ tính QC Đạt (L21, T09)

- **Backend** `supplycore/api/frontend.py::stock_balance`: thêm cờ `available` mỗi dòng
  = `qc_status == 'Accepted' AND NOT blocked`. Vẫn trả mọi dòng (giữ hiển thị + badge).
- **Frontend** `frontend/src/pages/StockBalance.vue`: KPI đổi thành **"Tồn khả dụng (QC Đạt)"**
  + **"Giá trị khả dụng"** (chỉ cộng dòng `available`) và thêm **"Tồn chờ xử lý (chưa QC / từ chối / khoá)"**.
  Trước đây KPI cộng cả lô Pending/Rejected/blocked → thổi phồng tồn.

**Kiểm thử:**
```
PASS stock_balance trả field 'available' (100/100 dòng), available chỉ gồm Accepted & không khoá (0 sai)
```

## 4. Tỷ lệ BHYT 0–100% (T17)

**File:** `…/doctype/sc_patient/sc_patient.py` → `_validate_bhyt_rate` (`SC-E031 BHYT_RATE_RANGE`).
Chặn `bhyt_payment_rate` < 0 hoặc > 100. (Field này là nguồn nhập thật; ở phiếu Cấp phát
nó `read_only`/fetch từ bệnh nhân nên 150% chỉ vào được từ master bệnh nhân.)

**Kiểm thử:** `PASS bhyt=150/-1 → SC-E031 ; 80/100/None → hợp lệ`.

## 5. Trang Người dùng & Quyền — race condition (L01)

**File:** `frontend/src/pages/Users.vue`
- Quyết định quyền dựa trên **access store** (`access.menu` = source of truth, load ở router guard),
  fallback `auth.user.roles`.
- Khi `!accessReady` → hiện "Đang kiểm tra quyền…" thay vì banner "Cấm" (hết cảnh phải F5).
- `onMounted` await `access.load()` rồi mới gọi API admin; thêm `watch(access.loaded)` để nạp
  danh sách khi guard load xong.

**Kiểm thử:** `npm run build` OK (208 modules, không lỗi).
