1. Tổng quan: nhóm chạy Frappe/ERPNext như thế nào?

1.1 Ba cách chạy — nhóm dùng cả ba, cho ba mục đích khác nhau

Frappe là bộ khung (framework) để làm phần mềm quản trị, viết bằng Python. ERPNext là bộ ứng dụng ERP dựng sẵn trên Frappe. bench là công cụ dòng lệnh để quản lý tất cả: tạo site, cài app, chạy máy chủ, chạy tác vụ nền.

3. Cài từ máy trắng đến chạy được site đầu tiên

Phần này giả định bạn có một máy Ubuntu 22.04 hoặc 24.04 sạch. Làm tuần tự từ trên xuống, đừng nhảy cóc.

Bước 0 — Chuẩn bị tài khoản

Làm gì: Đừng cài Frappe bằng tài khoản root. Frappe cần một tài khoản người dùng thường có quyền sudo.

whoami                    # xem mình đang là ai
sudo -v                   # thử quyền sudo — nếu hỏi mật khẩu là có quyền

Bước 1 — Cài các gói hệ thống

Làm gì: Cài sẵn những phần mềm nền mà Frappe cần trước khi bản thân Frappe cài được.

sudo apt update
sudo apt install -y git python3-dev python3-pip python3-venv \
    software-properties-common mariadb-server mariadb-client \
    redis-server curl xvfb libfontconfig wkhtmltopdf \
    libmysqlclient-dev build-essential

Giải thích từng nhóm:

  • python3-dev, build-essential — để biên dịch vài thư viện Python cần mã máy.
  • mariadb-server — cơ sở dữ liệu (kho chứa dữ liệu).
  • redis-server — bộ nhớ tạm & hàng đợi.
  • wkhtmltopdf, xvfb, libfontconfig — bộ ba để in phiếu/hóa đơn ra PDF. Thiếu là in hỏng.
Lỗi hay gặp E: Unable to locate package → bạn quên chạy sudo apt update trước.
PDF in ra trắng trơn hoặc mất chữ tiếng Việt → thiếu libfontconfig/xvfb, hoặc bản wkhtmltopdf không có patch Qt. Bản đúng là 0.12.6.

Bước 2 — Cấu hình MariaDB

Làm gì: Frappe bắt buộc bảng mã utf8mb4 để lưu được tiếng Việt có dấu và emoji.

sudo mysql_secure_installation      # đặt mật khẩu root, trả lời Y cho các câu hỏi bảo mật
sudo nano /etc/mysql/my.cnf

Thêm vào file my.cnf:

[mysqld]
character-set-client-handshake = FALSE
character-set-server = utf8mb4
collation-server = utf8mb4_unicode_ci

[mysql]
default-character-set = utf8mb4
sudo systemctl restart mariadb
sudo systemctl enable mariadb      # tự bật khi khởi động máy
Lỗi hay gặp Incorrect string value: '\xC3\xA0...' khi lưu tiếng Việt → chưa đặt utf8mb4, hoặc đặt rồi mà quên restart MariaDB.

Bước 3 — Cài Node.js 18 qua nvm

Làm gì: Frappe v15 cần Node 18. nvm cho phép cài nhiều bản Node và chuyển qua lại — an toàn hơn cài thẳng vào hệ thống.

curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
source ~/.bashrc
nvm install 18
nvm use 18
node --version            # phải ra v18.x
npm install -g yarn
yarn --version            # dự án dùng yarn 1.22.x
Lỗi hay gặp nvm: command not found sau khi cài → mở terminal mới, hoặc chạy source ~/.bashrc.
Rất hay gặp với supervisor/systemd: tiến trình nền không đọc ~/.bashrc nên không thấy node. Đó chính là lý do Procfile của dự án ghi đường dẫn tuyệt đối: /home/hoangvietyeuem/.nvm/versions/node/v18.20.8/bin/node.

7. Tóm tắt: điều nên nhớ và điều cần hỏi

7.1 Bảy điều dễ vấp nhất

  1. MariaDB đang failed trên máy này → khởi động trước khi làm bất cứ gì (mục 1.2).
  2. yarn build là bước riêng, bench build không build giao diện Vue (mục 3, Bước 8).
  3. Hard refresh (Ctrl+Shift+R) sau mỗi lần build, vì service worker giữ bản cũ.
  4. Clone repo về sẽ không có .claude/ — mất hết skill, phải xin chép tay (mục 4b).
  5. Không có CI khi mở PR — phải tự chạy test (mục 4d, 4g).
  6. Không có linter/pre-commit — chất lượng dựa vào kỷ luật cá nhân (mục 4h).
  7. Dùng yarn, không dùng npm ở frontend/ dù có cả hai lockfile (mục 4f).

7.2 Sáu câu nên hỏi người trong nhóm ngay ngày đầu

  1. erpnext đang ở nhánh develop — cố ý hay nhầm? Site có thực sự cài erpnext không?
  2. App miyano_portal quan hệ thế nào với SupplyCore? Có đang dùng không?
  3. Remote miyano khác origin ở điểm nào? Push vào đâu?
  4. Quy trình Pull Request & review cụ thể ra sao? Ai duyệt? Nhánh nào được bảo vệ?
  5. Tôi lấy thư mục .claude/skills/ ở đâu để có bộ skill giống mọi người?
  6. Có nên bổ sung CLAUDE.md và pre-commit không? Ai quyết?
Điểm mạnh của dự án — đáng học theo Dù thiếu vài công cụ tự động, dự án này có những thói quen rất tốt: chú thích code bằng tiếng Việt giải thích LÝ DO (không chỉ mô tả code làm gì), commit message có phần thân dài ghi lại bối cảnh quyết định, CI kiểm tra hệ quả thật (curl vào asset đã build, không chỉ xem lệnh có chạy xong), và tài liệu thừa nhận giới hạn thay vì tô hồng (workflow ghi rõ runner nào sẽ fail và vì sao).
